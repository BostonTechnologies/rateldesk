# RatelDesk 0.1.4-beta.12

- Support groups can own incident, request and change queues. The database upgrade keeps existing tickets and their history in Main Queue. [#512](https://github.com/BostonTechnologies/RatelDesk/issues/512)
- Custom roles can grant all authorized queues, active memberships or selected groups. Ticket data and related resources use the same organization, module and queue checks. [#513](https://github.com/BostonTechnologies/RatelDesk/issues/513) · [#514](https://github.com/BostonTechnologies/RatelDesk/issues/514)
- Old standalone ticket image URLs now require a current staff session and queue access. Customers can still view permitted content through their recipient-bound ticket link. [#514](https://github.com/BostonTechnologies/RatelDesk/issues/514)
- Staff can filter ticket workspaces by queue, transfer eligible tickets, and claim tickets in their assigned queues. [#515](https://github.com/BostonTechnologies/RatelDesk/issues/515)
- Queue assignments can send an authenticated ticket link to eligible members. The paired incident receiver supports an explicitly negotiated v3 queue route alongside the existing v1 and v2 contracts. [#516](https://github.com/BostonTechnologies/RatelDesk/issues/516) · [Receiver contract](https://github.com/BostonTechnologies/RatelDesk/blob/main/docs/contracts/rateldesk-incident-create.v3.md)
- Retry releases the hold owned by the failed attempt and retains the archived provider diagnostic. It can resume an unstarted retry left pending by beta.11 when the previous failure owns the hold. [#508](https://github.com/BostonTechnologies/RatelDesk/issues/508)
- Execution readiness identifies missing, revoked and changed saved-account approvals and directs operators to **Paired Run as** in NetRatel. [Paired issue follow-up](https://github.com/BostonTechnologies/RatelDesk/issues/508#issuecomment-7221642808)

Upgrade NetRatel to 0.1.7-beta.6 first. Review the saved-account scope, refresh readiness, and retry the rejected task after correcting the configuration. The installed Windows on-behalf Add and Remove journey and published-artifact receipt timing remain pending owner acceptance. [Recovery guide](https://github.com/BostonTechnologies/RatelDesk/blob/main/docs/integrations/netratel-pairing.md#recover-a-rejected-request)

The matching v3 writer remains tracked in NetRatel #862. [RatelDesk acceptance](https://github.com/BostonTechnologies/RatelDesk/issues/517)
