# 0.1.3-beta.7 — OIDC integration ownership

An explicitly authorized OIDC instance administrator could sign in and see
`HelpdeskAdmin`, yet Integration returned HTTP 403 because no application
credential owner had been persisted. Successful administrator provisioning now
creates one passwordless owner bound to the validated issuer and subject in the
existing Identity login store. Credential and system-connection management can
resolve that owner without creating a customer-contact association.

Account disablement remains authoritative, and provisioning never reenables an
account. Provider claims and explicit API mappings still determine current
administrator access. Resolving a fresh token without that authority updates
the persisted administrator projection used by owned credentials. Matching
email addresses do not associate accounts. Existing local and customer-linked
OIDC ownership is unchanged. There is no schema migration.

## Validation and operator checks

Signed-token API regressions cover repeated provisioning, credential listing,
system-connection listing, passwordless ownership, disabled accounts, admin-claim
removal, same-email/different-subject denial and invalid issuer/audience/signature
or expired tokens. Related ownership and effective-access regressions are part
of focused validation. Hosted PR/main checks and release distribution still
need their own successful receipts.

After deploying, sign out and in through the configured provider as an intended
instance administrator. Open **Administration → Integration** and check both
credentials and system connections. Verify a scoped user cannot manage instance
connections; verify account disablement and a fresh non-admin token deny access.
Then use the ordinary system pairing workflow for the intended peer. A successful
build or release does not establish this deployed acceptance.

Provider tokens can retain old claims until expiry or refresh. Disable the
application account for immediate local denial. See [OIDC account ownership](../security/rbac.md#oidc-account-ownership).
