# 0.1.2-beta.12

Repairs the oversized HTTP MCP upload failure observed in the beta.11 campaign
and makes the remaining laptop acceptance prerequisites explicit.

## Oversized upload response

The MCP host and Web gateway now consume a bounded decoded-body prefix before
rejecting an ordinary declared oversized upload. A client that sends the full
30,000,001-byte boundary probe before reading its response receives the structured
HTTP 413 instead of losing the response during an unread-body drain. Known
oversized uploads use a pooled discard buffer and do not spill their body to disk.

The accepted body limit remains 30,000,000 bytes by default. Tighter configured
limits, finite framing budgets, request cancellation, and immediate rejection
for `Expect: 100-continue` or declarations beyond the wire budget remain in place.
The guard consumes at most the decoded limit plus one byte; it does not promise
an unlimited drain for arbitrarily large or incomplete uploads.

Real socket regression coverage includes a client that finishes uploading before
reading, an outer reverse proxy, both direct MCP and Web gateway paths, and both
`/mcp` aliases. Existing chunked, malformed JSON, duplicate-argument and
concurrency checks remain applicable.

## Laptop acceptance

The [beta.12 laptop guide](../mcp-http/beta12-laptop-campaign.md) and
[validator](../../tools/ci/validate-beta12-campaign.py) retain all 390 operations,
103 domain cases, 86 historical obligations and nine cleanup assertions.
The [residual fixture map](../../tools/ci/beta12-residual-fixtures.json) identifies
the 59 operations left unpassed by beta.11 across twelve concrete fixture tracks.
Successful basic chat or direct mail no longer stands in for advanced recovery,
import, interaction, provider or actor setup.

New campaign workspaces start with fresh `NOT_RUN` receipts. The mapping planner
reports candidate domain/history mappings from already validated current-release
evidence and does not change outcomes. Effective transport configuration must be
captured independently for the Web and MCP host even when using default limits.
The guide preserves matching baseline scopes and the post-functional soak.

The operation contract is unchanged: 37 tools, 390 operations, catalog revision
`2026-10-25.beta11-contracts-v25`. The beta.11 revision name is intentional;
beta.12 changes transport handling and campaign tooling rather than tool schemas.

## Delivery and evidence

The supplied beta.11 campaign remains `NOT_READY`: 324 operation positives,
seven fixed Local/HTTP exclusions and 59 unpassed operations. Its original
evidence is unchanged. Source validation and public distribution have separate
receipts from a fresh deployed beta.12 acceptance campaign.

Delivery is tracked by [#270](https://github.com/BostonTechnologies/RatelDesk/issues/270).
The owner deploys the published artifacts; the laptop agent verifies those exact
identities before testing. Deployed acceptance remains tracked by
[#219](https://github.com/BostonTechnologies/RatelDesk/issues/219).

Publication uses the existing hosted workflow and preserves CLI/stdio native
archives, deployment collateral, checksums, release manifests, and the API, Web
and HTTP MCP image families. Prerelease publication leaves stable `latest`
unchanged.
