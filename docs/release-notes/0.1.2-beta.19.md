# 0.1.2-beta.19 candidate

This candidate includes two repairs found during deployed campaign acceptance:

- SQLite scheduler connections use SQLite's full mutex mode when the job
  provider shares a connection with its lock heartbeat. The regression tests
  verify the native mutex and run real background jobs while the heartbeat is
  active. PostgreSQL storage configuration is unchanged. This prevents the
  identified unsafe connection-sharing configuration; it does not repair an
  already damaged scheduler database.
- The login layout accommodates narrow viewports with enlarged text. This
  addresses the remaining overflow found in the long-brand login checks.

The product version remains owned by the root `Directory.Build.props`. The
existing 390 operations and their campaign requirements remain in scope.

Publication follows reviewed PR/main checks and the existing hosted release
workflow. Published prerelease assets remain immutable. All three image
families, both image architectures and the CLI/stdio archives retain their
existing distribution contract.

Source tests and release publication do not establish deployed acceptance.
Fresh scheduler execution through a real deadline, the complete login checks,
the remaining operation and historical requirements, independent cleanup, the
post-functional soak and strict evidence validation remain required under
[#219](https://github.com/BostonTechnologies/RatelDesk/issues/219).
