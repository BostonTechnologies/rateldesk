# 0.1.2 — MCP administration and investigations

This stable release line brings together the 0.1.2 beta series, including the
repairs verified against published beta.20. Version metadata and these notes
prepare the stable release; public artifacts and channel promotion are verified
separately through [release engineering](../releases/README.md).

## Setup and administration

- URL-first CLI, stdio and HTTP MCP setup preserves explicit target and client
  identities. Host setup supports reviewed adoption, deployment changes and
  fresh verification through the declared deployment owner.
- Explicit owner-administration consent enables bounded cross-organization
  operations. Current account authority, organization access, credential purpose,
  resource binding, expiry and revocation remain enforced on each request.
- Typed MCP operations cover ticket workflows, approvals, attachments, mail and
  recovery, datasets, forms, SLA, support routing, system connections and
  account administration. Confirmation and independent outcome checks remain
  part of operations that change state.
- Integration consolidates system connections, account API/MCP credentials and
  NetClaw. Versioned MCP policies narrow an existing credential's authority;
  NetRatel execution admission remains the responsibility of NetRatel.

## Investigations and workflow correctness

- Saved prompt guidance and scoped incident, request, change and task context
  accompany explicitly sent AI investigations. Search and ticket previews retain
  the caller's current access bounds. Native AI conversations require PostgreSQL
  and a configured provider.
- NetRatel callbacks authenticate and correlate the current execution attempt.
  An early callback receives a retryable response until normal acknowledgement
  establishes execution identity. Unknown outcomes hold automatic and manual
  retries for reconciliation; a later known result can resolve the same hold.
- Approval, assignment and concurrent lifecycle operations preserve their
  decision fences, audit records and notification intent. Worklog and timeline
  repairs retain authoritative effort and transactional provenance.
- Mail delivery records definite, partial and uncertain outcomes. Recovery and
  queue controls preserve held effects and terminal history instead of treating
  uncertainty as permission to resend.

## Campaign repairs

- Scoped incident previews, account-only credential management and signed public
  ticket timelines respect their intended authorization paths.
- Login branding fits narrow screens and enlarged text; terminal shutdown
  cancels obsolete rendering work while retaining actual render failures.
- Dataset-bound text fields retain their supported type and binding when saved.
  Graph synchronization uses documented SharePoint search and paged ingestion.
- Unicode chat stays within the bounded receive limit. HTTP and stdio retain
  strict argument and request-body boundaries, including duplicate arguments.
- SQLite scheduler connections are serialized. PostgreSQL upgrades accept the
  retained predecessor index and automation-binding shapes while preserving
  business records, credentials and conversation history.

## Upgrading

Back up the database, attachments, API data-protection keys and protected
deployment configuration before upgrading. Preserve provider settings and key
material and use forward migrations through the
[deployment procedure](../deployment/self-hosting.md).

SQLite and PostgreSQL remain supported. Keep the existing distinction between
Local and external identity configuration and between account credentials,
NetRatel pairing and NetClaw pairing. See the
[MCP setup guide](../mcp-http/setup.md),
[pairing guide](../integrations/netratel-pairing.md) and
[automation reconciliation guidance](../integrations/netratel-orchestrator.md).
Review uncertain provider or mail outcomes before retrying them.

## Validation and distribution

The [owner acceptance record](../implementation/0.1.2-stable-acceptance.md)
identifies the tested beta.20 implementation, complete operation inventory,
domain/history requirements, six UI groups and post-functional soak. The owner
accepted a non-blocking cleanup exception for two disposable external test-mail
accounts; the historical strict receipt and its limitations remain preserved.

The product version is `0.1.2`, with canonical tag `v0.1.2`. Distribution retains
API, Web and HTTP MCP images for amd64/arm64; CLI and stdio archives for Linux
x64/arm64 and Windows x64; and the deployment archive, checksums, manifest and
third-party notices. Linux native archives require glibc. Container publication
retains SBOM and provenance.

The hosted workflow stages immutable versioned artifacts. After publication and
anonymous download/pull verification, the separate protected promotion workflow
updates `latest` to the exact stable digests. Publication does not deploy an
instance or enable its workers, senders or integrations.
