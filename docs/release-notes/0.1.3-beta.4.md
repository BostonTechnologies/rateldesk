# 0.1.3-beta.4

The UX campaign in [#345](https://github.com/BostonTechnologies/RatelDesk/issues/345)
covers ticket creation, state changes, guided Data Management and shared AI
Markdown tables. See the [implementation and delivery record](../implementation/0.1.3-beta.4-ux.md)
for validation and publication receipts.

## UX changes

- Request, incident and change creation use searchable organization choices.
  Change requester and approver selections search authorized names/email and
  keep stable selected identifiers. Lookup results are bounded after scope and
  search; existing list clients keep their complete-list contracts.
- Actionable state chips open a keyboard-accessible popup. Requests/incidents
  use their existing state operations; changes retain lifecycle, approval and
  template guards and show the lifecycle returned by the server.
- Data Management separates **Custom datasets** from **Built-in integrations**.
  Custom creation uses **Details → Schema → Review & create**, followed by
  optional ingestion-key creation. Rows, schema editing, API access, scripts and
  advanced diagnostics retain dedicated locations.
- Microsoft Graph setup uses **Connection → Choose datasets → Test access →
  Review & import**. Testing reads bounded samples without importing or changing
  settings/schedules/sync timestamps. Only explicit final save/import ingests
  the selected sources. Review explains replacement of records absent from Graph.
- Saved and streamed AI replies share semantic Markdown table rendering,
  contained horizontal scrolling and keyboard-accessible table-only copying.
  Code copying and inert HTML encoding remain intact.

## Retained main changes

This candidate also retains the beta.3 AI workspace corrections: actual received
tool payloads, compact Stop controls, contained header popups and the full-height
Investigation workspace. Historical exact-turn recovery remains tracked by
[#308](https://github.com/BostonTechnologies/RatelDesk/issues/308).

The accepted #318 distribution changes remain in place, including reduced
client dependency payloads, API runtime-specific publishing, shared-host
telemetry ownership and deduplicated packaged helpers/documentation. The #344
Web repair retains IANA timezones and the native archive/image acceptance
contract. This feature campaign does not reverse the packaging work or change
the supported deployment targets.

## Upgrade

The SQLite and PostgreSQL migration chains add `GraphDatasetImportRuns` and its
indexes to retain import outcomes and reconcile interrupted work. Existing
dataset definitions, rows, ingestion credentials and Graph settings remain in
place. Apply the normal application upgrade/migration procedure; do not recreate
datasets or rotate keys merely to adopt the new workspace. Native AI chat keeps
its existing PostgreSQL requirement; the other supported features retain both
database providers.

Existing dataset-create callers may omit the new request identifier and retain
the default schema behavior. The current MCP contract revision is
`2026-11-05.beta4-contracts-v27`: its optional dataset-create request ID supports
idempotent drafts without adding operations or changing confirmation/authority.

## Owner retest

1. Create an incident, request and change. Search beyond the initial suggestions,
   switch organizations and confirm requester/approver/assignment IDs after save
   and reload. Exercise a scoped nonadministrator and duplicate names.
2. Open state chips by mouse and keyboard on all three lists. Dismiss without
   saving, select a permitted state, inspect a denied/guarded transition and
   confirm filtered membership and persisted state after reload.
3. In Data Management, use Back/Cancel in both wizards. Create a custom dataset
   with and without a key. Test Graph access before importing, inspect each
   source result and choose recurring UTC scheduling explicitly.
4. In Chat, Investigations and a ticket assistant, stream/save/reopen a response
   with multiple wide tables. Copy one table and code separately; check narrow
   fullscreen, both themes, keyboard access and 200% zoom.

Real Microsoft Graph permissions and live native-daemon behavior require owner
acceptance against the configured external services; deterministic fixture
results establish source behavior separately.
