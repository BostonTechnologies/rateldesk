# 0.1.1 — workspace and operational controls

This stable release line brings together the changes since 0.1.0, including
the 0.1.1 beta series and the workspace improvements below. Source release notes
describe behavior; publication, public downloads and stable-channel promotion
are verified separately through the [release procedure](../releases/README.md).

## Workspace improvements

- Self-service search uses a bounded desktop toolbar and fits narrow screens.
- Incident, request and change lists share customer, requester, state, assignee,
  priority and time filters. Filtering and totals use the authorized dataset
  before pagination. The obsolete AI-only list control is removed; the AI
  Assistant, conversations and provenance remain available.
- Original email HTML has an isolated readable canvas, with a themed plain-text
  alternative. Preview and detail controls retain the application theme.
- Ticket details use compact shared sections, reliable category selection and
  activity headers with inline counts. Existing assignment eligibility and
  Save/Revert behavior remain part of the ticket editor.
- Operations brings SLA and Workflows into two tabs. Background jobs remain
  under Workflows; Notifications is a sibling in the Operations navigation group.
  Existing Operations bookmarks remain supported.
- Data Management and Support Routing group their existing tasks into focused
  views. Custom roles appear first, with built-in roles separately protected.
  Tenant SLA settings separate Policies, Working calendars and Reporting.
- Pending Emails uses server-side paging and filtering, with explicit retry,
  cancellation and queue-removal controls. Queue removal retains ticket history.
  Submitted or uncertain mail cannot be recalled by these controls.
- Navigation keeps labels on one line with accessible full text and a responsive
  drawer. All views retain their existing scope and authorization boundaries.

## Changes accumulated since 0.1.0

- Mailbox ingestion supports Graph, IMAP and POP3 with tenant overrides, durable
  receipts, worker ownership, first-import boundaries and bounded historical
  recovery. Outgoing delivery is bound to its selected mailbox and preserves
  sender revisions, partial-recipient outcomes and uncertain-delivery review.
- The Integration hub includes NetClaw pairing, provider status and recovery,
  and NetRatel pairing codes with independent, persisted connection capabilities.
  The pairing-code cutover replaces retired service-link authority while
  preserving installation identity and business history.
- Registered-source incident creation has durable idempotency receipts and
  authenticated provider coverage. Connection changes and background recovery
  recheck current authority instead of trusting stale snapshots.
- Local and external account sign-in, first-paint theme behavior and branding
  have received corrections. Ticket assignment uses one bounded, searchable
  selector with explicit unassignment and per-module eligibility.
- The Web gateway supports a single public origin for API and selected HTTP MCP
  routes. CLI, stdio MCP and HTTP MCP configuration keep their identities and
  target bindings separate, with explicit setup and read-only diagnostics.
- Browser pairing and terminal setup provide bounded account credential grants.
  The categorized documentation and packaged guides cover setup, gateway,
  integrations, security and release recovery.

## Upgrading

Back up the application and identity databases, storage and protected settings
before upgrading. Keep their existing provider and key material. Apply forward
migrations using the documented [deployment procedure](../deployment/self-hosting.md).
The beta.22-to-stable path preserves settings, identity records, ticket history,
role assignments, category associations and pending-delivery review state.
Queue controls do not turn uncertain delivery into a safe automatic retry.

For upgrades from releases before the pairing-code cutover, follow the
[NetRatel pairing guide](../integrations/netratel-pairing.md) and pair both
products afresh. Existing account/CLI credentials and NetClaw configuration use
their own lifecycles. See the [Web gateway guide](../deployment/web-gateway.md)
when adopting one public origin and the [integration guides](../integrations/README.md)
for explicit client setup.

## Distribution

The product version is `0.1.1`, without a prerelease suffix. The canonical release
tag is `v0.1.1`. The existing workflow produces API, Web and HTTP MCP images for
amd64/arm64; CLI and stdio MCP archives for Linux x64/arm64 and Windows x64; and
the deployment archive, manifests, checksums and license notices. Container
builds retain SBOM and provenance. Linux native archives require glibc.

Stable publication follows complete draft-artifact verification and anonymous
download/pull checks. The separate protected promotion workflow reuses the exact
verified digests to update `latest`; it does not rebuild published artifacts.
Publishing this software does not deploy a production instance.
