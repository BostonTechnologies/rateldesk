# 0.1.2-beta.2 — MCP setup and incident-search corrections

This focused follow-up to beta.1 addresses [#191–#195](https://github.com/BostonTechnologies/rateldesk/issues/190).
It preserves MCP-purpose/resource-bound gateway access, API-issued request-scoped
execution tokens, exact grants, separate private profiles and status-only
temporary verification. Generic ID-suffixed query filtering remains the separate
non-blocking [audit #196](https://github.com/BostonTechnologies/rateldesk/issues/196).

## Changes

- The Docker-host launcher checks the selected Compose implementation's actual
  required capabilities before consent or deployment changes. Safe diagnostics
  identify the missing feature and supported host action. Deliberately selected
  Docker configuration/context/host/TLS settings continue into follow-up commands.
- The complete reviewed proposal migrates the recognized legacy selected
  outbound config-file mount to protected runtime storage. It preserves effective
  settings, external downstream identities and unrelated/shared resources;
  operators do not hand-edit the approved export to repair the collision.
- `helpdesk_incidents` list maps `request.query` to API `q` before authorized
  filtering, counts and paging. Direct `q` remains supported; equal trimmed
  aliases deduplicate and conflicting/malformed aliases fail before network I/O.
  Other tools and the generic query builder retain their contracts.
- The compact approval view exposes purpose, URL/code, status/expiry and actions
  before extended Details. Back follows host, ordinary-client and temporary
  verifier contexts and prevents obsolete approval attempts advancing new work.
- [Local-account URL-first setup](../mcp-http/setup.md) leads the guides, with
  explicit host/client/verifier decisions, saved-profile checks and changed-source
  recovery. The full configuration and external Authentik/OAuth reference remains.

## Upgrade and owner retest

Use Web/API/HTTP MCP/tools from the same verified release. Preserve the database,
API key ring, attachments, ingress, instance/API target, protected configuration
and ordinary client volume. Back up through the existing deployment owner.

From the extracted deployment tools directory **on the Docker host**:

```sh
./setup-http-mcp.sh
# Review/approve and apply the complete proposal through its declared owner.
./setup-http-mcp.sh --verify
# Optional separate ordinary client approval:
./setup-http-mcp.sh --target http-client -- --profile incident-reader
```

Keep the selected Docker environment on all commands. Confirm the legacy mapping
is migrated in the proposal and recreation succeeds without export repair. Run
verification from a fresh process and confirm restricted-verifier cleanup. Reload
the retained explicit ordinary profile with the [doctor template](../mcp-http/setup.md#check-or-reconnect-a-saved-client),
then check permitted incident list/get and a unique impossible incident search:
`items: []`, `totalCount: 0` with `includeTotal=true`. Confirm an ungranted read
remains denied. Use synthetic/disposable data; verification performs no business
writes, mail or workflow execution.

If sources changed, run ordinary setup with the same source/storage/owner
selectors and obtain new review/approval before apply and verification. An
unchanged applied generation resumes with `--verify`. Do not reuse a stale hash,
edit protected receipts, reset ordinary identities or silently extend expiry.
