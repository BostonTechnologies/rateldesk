# RatelDesk 0.1.3-beta.9

Repairs [#378](https://github.com/BostonTechnologies/RatelDesk/issues/378) with
NetRatel #727.

The request workflow browses canonical NetRatel jobs through the exact saved
connection, including HA, explicit nodes, selectors and declared runtime inputs.
Typed targeting replaces the legacy singular-client requirement. Empty catalogues
remain browsable and refreshable. Create job uses discovered tenant choices,
executable commands, inputs and native execution policy, preserving failed drafts.
Catalogue errors retain sanitized operation, HTTP status, stable code and reference.

Execution tracks NetRatel's aggregate parent and final outcome; existing task
correlation, binding isolation, unknown outcomes and callback replay remain in
place. The compatible pair and upgrade/retest procedure are in
[the pairing guide](../integrations/netratel-pairing.md#target-aware-self-service-automation).
Upgrade NetRatel 0.1.5-beta.4 first; keep the current saved connections and keys.
RatelDesk adds no persistence migration and retains SQLite/PostgreSQL support.

Required PR/main checks, focused rendered/service/provider tests, optional
source-pair/native acceptance and public distribution verification are separate
receipts. Publication does not establish owner production deployment acceptance.
