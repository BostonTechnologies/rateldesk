# RatelDesk 0.1.4-beta.2

## Changes in beta.2

- Integration credentials and CLI/MCP approval require tenant administration in the selected tenant. Instance administrators retain instance-wide access. [#432](https://github.com/BostonTechnologies/RatelDesk/issues/432)
- Connected NetClaw scheduled reports stay attached to the originating conversation and save the matching final reply after the original turn has finished. This was exercised with NetClaw 0.28.2 in organization Chat and ticket contextual AI. [#351](https://github.com/BostonTechnologies/RatelDesk/issues/351) · [#438](https://github.com/BostonTechnologies/RatelDesk/pull/438)
- Failed NetRatel capability checks now carry their phase, error code, retryability and attempt reference into generated incidents as well as the linked task and workflow. [#430](https://github.com/BostonTechnologies/RatelDesk/issues/430)

## Also included

- Chat and AI Ops support OpenAI Agents API profiles using the Codex harness alongside NetClaw. Live managed OpenAI acceptance requires an operator's project credentials. [#436](https://github.com/BostonTechnologies/RatelDesk/issues/436)
- Slopwatch 0.5.0 uses a shared reviewed baseline and enforces Info-level findings in local and hosted checks. [#434](https://github.com/BostonTechnologies/RatelDesk/issues/434)
- MCP can read authorized incoming and outgoing ticket relations from the same universal relation store used by contextual AI. [#433](https://github.com/BostonTechnologies/RatelDesk/issues/433)
- Chat preserves unsent multiline drafts after navigation or refresh. Enter sends and Alt+Enter inserts a newline. [#431](https://github.com/BostonTechnologies/RatelDesk/issues/431) · [#351](https://github.com/BostonTechnologies/RatelDesk/issues/351)
- CLI, stdio MCP and deployment archives ship selected operator guides and are held to per-download size budgets. [#428](https://github.com/BostonTechnologies/RatelDesk/issues/428)
- Organization Chat and contextual AI share the fullscreen workspace, trace preferences and recovery controls. [#305](https://github.com/BostonTechnologies/RatelDesk/issues/305)

## Testing limits

- Disconnects and daemon restarts can still leave scheduled or interrupted outcomes unknown. Exact historical replay and shared-daemon reconnect acceptance remain open. [#308](https://github.com/BostonTechnologies/RatelDesk/issues/308) · [#351](https://github.com/BostonTechnologies/RatelDesk/issues/351) · [#305](https://github.com/BostonTechnologies/RatelDesk/issues/305)
