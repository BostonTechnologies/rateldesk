# RatelDesk 0.1.4-beta.7

- Changes can be cancelled from the table or details, including incomplete drafts. Administrators can cancel selected rows and review each result. Approved or in-progress changes with a complete plan can record **Implemented - Failed**. Both outcomes appear in History with their saved audit trail. [#497](https://github.com/BostonTechnologies/RatelDesk/issues/497) · [PR #500](https://github.com/BostonTechnologies/RatelDesk/pull/500)
- The authenticated Timeline opens and restores its saved selection across Incidents, Requests, and Changes. Read and contribution permissions still apply in each workspace. [#498](https://github.com/BostonTechnologies/RatelDesk/issues/498) · [PR #499](https://github.com/BostonTechnologies/RatelDesk/pull/499)

## Upgrade and retest

Pin the deployment to `0.1.4-beta.7` or the image digests in the release manifest. Try the following with synthetic records before upgrading an existing instance.

1. Cancel an incomplete Draft with the explanation blank. Reload its details and confirm it appears in **History**.
2. As a Helpdesk administrator, select a page of drafts, run **Cancel selected**, and check the per-record results and remaining Active count.
3. Record **Implemented - Failed** on an approved or in-progress change with a complete plan and a reason. Find it in **History** and confirm the saved reason.
4. Open an incident on **Messages**, switch to **Timeline**, check the entries, and open another tab. Return to **Timeline**, reload the incident, and switch tabs again.

Two synthetic browser checks still reproduce beta.6 failures. The End key fails to focus the Relations tab, and the Requests manager test sees an assignee chooser where the fixture expects it hidden. [Browser verification notes](https://github.com/BostonTechnologies/RatelDesk/pull/499)
