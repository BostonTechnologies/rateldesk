# 0.1.2-beta.7 candidate — automation retry and form repairs

Generated automation tasks retain the template Auto Start setting, including
an upgrade backfill for existing exact form/template matches. Explicit selected
single and bulk retries dispatch independently of that setting, retain previous
attempt details, and persist a new attempt correlation before provider submission.
Uncertain submissions still require reconciliation. Retry requires the companion
NetRatel terminal-attempt admission repair; upgrading RatelDesk alone is insufficient.

The form editor permits disabled bindings, retains that selection on newly
created bindings, and identifies partial binding-save failures with their HTTP
status. Closed ticket-list schemas reject unsupported fields before API reads.

This is a candidate description. Required CI, reviewed merge, immutable hosted
publication, deployed pair verification and fresh campaign evidence must establish
their own results. The full acceptance register under #219 remains open; neither
source tests nor release publication closes live identity/provider prerequisites.
Preserve saved mail controls and historical receipts. This beta does not move
the stable channel.
