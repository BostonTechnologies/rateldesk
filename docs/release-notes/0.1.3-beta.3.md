# 0.1.3-beta.3

Corrects the beta.2 AI workspace feedback in
[#313](https://github.com/BostonTechnologies/RatelDesk/issues/313),
[#314](https://github.com/BostonTechnologies/RatelDesk/issues/314) and
[#315](https://github.com/BostonTechnologies/RatelDesk/issues/315).

## Changes

- Tool traces retain the actual received tool name, arguments, full result and
  failure detail through ingestion, persistence, API delivery and reload.
  Plain text, Markdown, JSON, skill `Name` and `_rationale` remain inspectable
  and copyable. The existing conversation access checks still apply. Payloads
  render as inert text and are not added to general logs or public evidence.
- Normal processing keeps a compact Working indicator and header Stop action.
  The explanation and confirmation appear when Stop waiting is invoked.
  Cancelling keeps waiting; accepting stops locally without resending.
- Netclaw status sits at the right of the workspace/assistant header, including
  fullscreen. A fresh native Connected observation uses a green outline, text
  and dot. Saved verification alone remains distinct from a live connection.
- Connection and display settings popups use the browser top layer, align to
  their buttons and shift/flip within the viewport on resize, scroll and zoom.
  Mixed short/long tool rows and expanded details share a consistent left edge
  in compact and expanded presentation.
- Investigations uses one compact toolbar, three short bordered counters and
  a narrow history pane beside the conversation. The panes fill the remaining
  viewport height, with transcript scrolling and a reachable composer.

## Upgrade and test

No new database migration is required. Native AI chat continues to require
PostgreSQL; other supported features retain SQLite and PostgreSQL support.
Older trace data that was previously discarded cannot be reconstructed. Legacy
records explain redaction/truncation; a new event with no supplied payload says
so explicitly. Changing display preferences cannot recover missing old data.

1. Start a fresh skill-load/tool-discovery turn. Expand arguments/results,
   copy them, reload, and compare them with what the daemon supplied. Include
   plain text, Markdown and JSON results.
2. During an ordinary turn, inspect the compact Working/Stop controls. Open
   Stop waiting, cancel, then confirm on a disposable turn. Confirm no resend.
3. In incident chat, Chat and Investigations, inspect the right-hand connection
   badge. Open its popup and display settings, maximise/restore, scroll and
   resize. Check compact/expanded rows, narrow windows, zoom and both themes.
4. Open a long investigation at desktop and short laptop sizes. Confirm its
   transcript/composer remain usable, and exercise search, status filters,
   decisions, recovery and archived views.

Automated native-contract/persistence/API tests and browser fixtures establish
source behavior with synthetic data. Fresh owner deployment and real-daemon
acceptance follow publication. The older tracking issues #305, #306, #307 and
#311 are reconciled with these corrections; their merged features are retained.

## Known recovery limitation

[#308](https://github.com/BostonTechnologies/RatelDesk/issues/308) tracks the
remaining exact-turn historical terminal/approval replay limitation. Connected
transport and confirmed admission do not prove a disconnected turn completed.
This beta preserves honest unknown recovery and never automatically resends.
See the [Netclaw operator guide](../integrations/netclaw.md).

## Distribution

Use exact `0.1.3-beta.3` image tags or release-manifest digests for
`ghcr.io/bostontechnologies/rateldesk-api`, `rateldesk-web` and
`rateldesk-mcp-http`, each supporting amd64 and arm64. The prerelease includes
seven CLI/stdio/deployment archives, `SHA256SUMS`, the manifest and its detached
checksum, plus image SBOM/provenance. The stable `latest` channel stays on its
separately approved release.
