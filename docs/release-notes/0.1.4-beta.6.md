# RatelDesk 0.1.4-beta.6

- Inline images are validated and normalized, and signed asset routes protect retained files. Private AI conversation changes require the original operator. [#465](https://github.com/BostonTechnologies/RatelDesk/issues/465) · [#466](https://github.com/BostonTechnologies/RatelDesk/issues/466)
- Public intake checks customer and organization eligibility before creating records and preserves existing customer profiles. The Web gateway and API share trusted client identity for admission limits, and CAPTCHA rendering and challenge storage have their own bounds. [#467](https://github.com/BostonTechnologies/RatelDesk/issues/467) · [#468](https://github.com/BostonTechnologies/RatelDesk/issues/468) · [#469](https://github.com/BostonTechnologies/RatelDesk/issues/469) · [#470](https://github.com/BostonTechnologies/RatelDesk/issues/470)
- Emailed ticket and approval links exchange once for scoped browser access. Public timelines omit internal staff identifiers, and signing out uses a protected form on desktop and mobile. [#471](https://github.com/BostonTechnologies/RatelDesk/issues/471) · [#472](https://github.com/BostonTechnologies/RatelDesk/issues/472) · [#473](https://github.com/BostonTechnologies/RatelDesk/issues/473)
- Hybrid sign-in fits the password form and organization sign-in action in the initial view on common laptop screens. [#490](https://github.com/BostonTechnologies/RatelDesk/issues/490) · [PR #493](https://github.com/BostonTechnologies/RatelDesk/pull/493)
- Catalogue items use explicit organization audiences across folders and forms. An eligible account can choose an organization when submitting a request and see its requests and tasks in that organization. [#491](https://github.com/BostonTechnologies/RatelDesk/issues/491) · [#492](https://github.com/BostonTechnologies/RatelDesk/issues/492) · [PR #494](https://github.com/BostonTechnologies/RatelDesk/pull/494)

## Upgrade and retest

SQLite and PostgreSQL apply forward migrations for public link grants and requester profiles. Legacy links retain their signed expiry within a 30-day compatibility window. Review catalogue items with empty audiences before sharing them with requesters. [Security release evidence](https://github.com/BostonTechnologies/RatelDesk/pull/474) · [Self-service migration evidence](https://github.com/BostonTechnologies/RatelDesk/pull/494)

1. Check both actions on the Hybrid sign-in page at 1280×720. Sign in and sign out using the desktop or mobile menu.
2. Submit a request in each of two authorized organizations. Confirm that each organization shows the correct history and task.
3. Open an emailed ticket link, choose Continue, and refresh the resulting page. Open a second ticket from a different email and confirm both tabs still display their own tickets.

Installed-instance verification of chat lifecycle telemetry and durable final counts is tracked separately. [#439](https://github.com/BostonTechnologies/RatelDesk/issues/439)
