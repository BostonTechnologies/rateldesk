# 0.1.1-beta.20 — NetRatel ↔ RatelDesk pairing-code cutover

Both products now use **Account → Integration credentials → System connections**.
Generate a five-minute code on either product; on the other, enter Address and
Pairing code, select **Pair & connect**, then select the authorized tenant and
organization/customer, edit the connection name, choose **Create incidents**
and/or **Run automation**, and select **Save** once.

The replacement removes the previous browser approval, recovery and manual
NR↔RD setup runtime. Forward migrations retire those connections, revoke their
credentials and disable obsolete bindings. Upgrade both products, then pair
and map afresh. No manual cleanup or installation identity reset is needed.
Installation/producer identities, signing keys, unrelated credentials, Netclaw
and incident/Flow/task history remain intact.

Saved connections support View, optional read-only Test and local-first Delete,
including peer outage. Pairing credentials only authorize setup; business use
requires the saved mapping, selected capabilities and current permissions.

See the [pairing and upgrade guide](../integrations/netratel-pairing.md).
Source/disposable-pair validation and publication integrity are recorded in the
linked tracking issues separately from the owner's deployed-beta acceptance.
