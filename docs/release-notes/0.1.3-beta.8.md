# 0.1.3-beta.8 — Operations and change workspaces

Pending Emails, Email Rules/Audit, Changes, Tasks and Notifications share compact
toolbars, accessible icon actions, restrained statuses, readable summaries and
bounded tables with native 25/50/100-row pagers. Exact technical identifiers and
diagnostics remain available through details and advanced lookup. Styles opt in
per workspace and use the configured theme tokens.

## Queue operations and audit history

Pending Emails supports explicit page selection or all authorized matching
deliveries, cross-page exclusions and a fixed selection reviewed before
cancellation/removal. The server records actor-bound membership and revisions,
then processes at most 50 targets per request. Progress, per-record conflicts
and skipped results survive reloads; resume uses the same operation. New
arrivals never enter that confirmed membership. Each queue change and its
receipt commit together; interrupted requests reconcile through those receipts.
Cancel/removal retain ticket/email history and do not send mail or recall a
previous submission. Existing individually reviewed retry paths remain separate.

Both database providers receive additive operation/target tables. Back up a test
instance before upgrading and allow its normal migration startup to finish.
Operation links are restricted to their initiating actor and existing management
authority is checked again while processing. Detailed outcome pages are
available through the operation results API.

Email audit queries now filter/count/page the complete independent history,
including matches older than the former newest-200 window. Seven headers align
with seven cells. Names and authorized tracking links replace prominent raw IDs;
unresolved entities retain exact IDs in copyable details without inventing a
historical name. Existing unpaged consumers remain compatible. Rule browsing,
clone-as-disabled, scoped precedence and enable/disable retain their semantics.

## Guided changes

Creation follows **Overview → Plan → Schedule & people → Review** using one
retained draft, a persistent footer and a deliberate content scroll region.
Standard, Normal and Emergency plans retain their distinct fields across type
changes. Each input has one label, with longer help behind a keyboard-accessible
help icon. Validation finds hidden-step errors and moves focus to the relevant
field. Permitted incomplete plans can be saved using **Create draft**; approval
and lifecycle submission remain explicit later actions. UTC schedule labels and
roundtrips are preserved. Failed saves and declined discard confirmations retain
the draft, and repeated submission is fenced.

Existing API/MCP callers retain their creation behavior when `saveAsDraft` is
omitted. MCP callers can explicitly choose a draft using `request.saveAsDraft`
(or the field on a bulk-create item), with existing confirmation and authority
checks. The current generated MCP catalog includes this optional field.

The detail view defaults to a readable plan summary with the same editing groups
behind **Edit plan**. Save/Revert, locked-state authority, approvals, categories,
activity, worklogs, attachments and return navigation remain available.

## Tasks and notifications

Tasks starts with **Assigned to me** off, including its first server request.
The table pages all tasks already authorized for the actor. Running appears as a
status. Local state, binding health and external reconciliation are independently
labelled; compact actions retain execution and recovery guards.

Notifications removes Reference from the default grid while retaining exact-ID
search, event/timeline details and navigation. Readable event/source summaries
and quiet read/unread presentation preserve raw payloads. Live arrivals and
reconnect gaps offer explicit refresh while holding the current rows, selection
and reading position. Failed receipt requests retain the selection and do not
claim successful read state; aggregate bulk responses reconcile actor-specific
receipts from the server.

## Owner installation and walkthrough

Use the public release's `SHA256SUMS`, `release-manifest.json` and detached
manifest checksum to verify the selected archive. CLI and stdio MCP archives
support Linux x64/ARM64 and Windows x64; the deployment archive contains the
existing Compose setup and categorized guides. Follow
[deployment setup](../deployment/README.md) and pin the three images to this beta
or the release manifest's immutable digests. Stable `latest` remains separate.

Use disposable, non-production records for these checks:

1. **Pending Emails:** filter a synthetic queue, select all matching, exclude rows
   on two pages and review the fixed count. Cancel, pause/resume and reload the
   operation link. Check conflicts and retained history, then remove cancelled
   entries. Exercise a reviewed retry separately; cancellation/removal should
   produce no outgoing submission.
2. **Email Rules/Audit:** page and filter rules, clone a disabled copy and inspect
   scoped reordering. Find an old audit failure using outcome/date/rule filters;
   inspect exact IDs and copied diagnostics, including an unresolved rule.
3. **Changes:** enter each change type across all four steps, switch types and
   return to check retained values. Save an incomplete draft, reopen it, edit its
   plan and schedule, and check Save/Revert and discard protection. Confirm it
   remains Draft until an authorized lifecycle action is taken.
4. **Tasks:** verify the initial all-authorized view, use the pager, toggle
   Assigned to me and distinguish Running, binding warnings and external
   reconciliation. Inspect permitted recovery without executing customer work.
5. **Notifications:** search an exact reference, inspect event/timeline details,
   mark a disposable selection read and verify actor-specific counts. Receive a
   synthetic live event or reconnect, check stable rows/selection and use the
   explicit refresh prompt.

Repeat the five surfaces in light/dark/custom themes at desktop, narrow width
and 200% browser zoom. Report the beta/source SHA, viewport/theme, steps and
diagnostic operation/event IDs with any defect.
