# 0.1.3-beta.2

This beta brings the AI workspace closer to the NetRatel source template and
addresses [#311](https://github.com/BostonTechnologies/RatelDesk/issues/311).

## Changes

- **Start typing immediately:** select an authorized organization in
  Operations → AI Ops → Chat. The welcome screen and quick-start cards lead to
  a ready composer. The first message saves the conversation and its automatic
  title atomically; a title form or preliminary Save is no longer required.
  Ctrl / Cmd + Enter sends; Enter adds a line. An interrupted first response
  offers an explicit retry using the same conversation and message IDs.
- **Shared conversation frame:** recent chats, search, optional New chat and
  the Netclaw setup gear occupy the sidebar. Compact archive, fullscreen and
  settings controls leave more room for the conversation. Display preferences
  live in a popover. Investigation context selection remains explicit.
- **Connection evidence:** the badge and details show saved verification and
  current native SignalR observations separately from API live updates. Missing
  or stale observations do not claim a connected daemon. Observation is
  read-only, scoped to current permissions and excludes credentials.
- **Navigation and account refresh:** AI Ops comes first under Operations,
  followed by Operations console and Notifications. Repeated authentication
  notifications for an unchanged principal preserve drafts; changed identity
  or access claims clear them.
- **Repository guidance:** install the pinned MIT-licensed
  [dotnet-skills references](../../.agents/skills/README.md), route applicable
  work through them in `AGENTS.md`, and pin Slopwatch as a local .NET tool with
  a baseline captured from the preceding main revision.

## Upgrade and test

No database migration is added by this beta. Upgrading from an earlier release
still applies any outstanding migrations, including beta.1's conversation scope
changes. Back up the database first. Native AI chat requires PostgreSQL; other
features retain SQLite and PostgreSQL support.

1. Open Chat, choose an organization, use a quick-start card and send once.
   Check the automatic title, reloadable link and a single operator message.
   Switch organizations with a draft and during a pending first send.
2. Reopen history, search, include archived chats and archive an idle chat.
   Inspect the settings popover, maximize/restore and keyboard focus in both
   themes and on a narrow screen.
3. Inspect the connection badge before and after a real native session starts.
   Compare saved verification, native observations and API updates. Disconnect
   the daemon and verify that stale or missing evidence remains honest.
4. Reopen investigations and ticket assistants. Check context, current access,
   long text/emoji messages and native approvals against a live daemon.

Automated API, PostgreSQL/SQLite and fixture browser checks verify source
behavior. The owner will perform fresh native-daemon acceptance after
publication; fixture screenshots do not establish live connectivity.

## Known recovery limitation

[#308](https://github.com/BostonTechnologies/RatelDesk/issues/308) remains open.
The supported join history does not establish durable, exact-message terminal
or approval replay. A disconnected admitted turn can still have an unknown
outcome, and a missed final report cannot reliably be restored from that
history. This UX update does not change that contract. Recovery does not
automatically resend the uncertain message. See the
[Netclaw operator guide](../integrations/netclaw.md).

## Distribution

Use exact `0.1.3-beta.2` tags or manifest digests for
`ghcr.io/bostontechnologies/rateldesk-api`, `rateldesk-web` and
`rateldesk-mcp-http`, each supporting amd64 and arm64. The prerelease includes
the existing seven CLI/stdio/deployment archives, `SHA256SUMS`, a release
manifest, and image SBOM/provenance. Verify checksums before use. The stable
`latest` channel remains on its separately approved release.
