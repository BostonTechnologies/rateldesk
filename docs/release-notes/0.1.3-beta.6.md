# 0.1.3-beta.6

This beta includes quiet configurable diagnostics and container retention (#358),
native delegated chat follow-ups (#355), the task-first request service editor
(#357), and bounded shared requester columns (#356). Production deployment is a
separate operator step.

## Changes

- API bootstrap/normal hosting, Web, HTTP/stdio MCP and AppHost use one validated
  Warning diagnostic default. `RatelDesk__Logging__MinimumLevel` and literal,
  longest-prefix category overrides enable Information/Debug without rebuilding.
  Admitted hosted events retain OpenTelemetry, notification and AI Ops delivery.
  An OTLP endpoint disables console by default;
  `Observability__ConsoleLogsEnabled` explicitly overrides that choice. When
  console is enabled, each admitted event produces one console record. Stdio stdout
  remains JSON-RPC-only. See [logging configuration](../deployment/application-logging.md).
- Repository-owned Compose recipes and new generated deployments use Docker
  json-file `200m` per file and five files, including the active file: about
  1 GB combined per container. Existing consumer driver/options remain owned by
  their deployment. See [retention and recreation](../deployment/self-hosting.md#container-log-retention).
- Connected Netclaw child follow-ups retain the original request, receiving
  owner and durable conversation after the initial parent turn. Later replies
  persist and render without another operator input, including refresh and
  fullscreen. Pending work blocks new sends, preserves approvals and has a
  fixed one-hour observation bound from original admission. Failed/no-reply/skipped
  outcomes stay visible.
  See [native behavior and limits](../integrations/netclaw.md#delegated-child-follow-ups).
- Service Explorer opens Workflow first, with a compact task navigator and
  adjacent selected-task editor. Form fields/setup share the same draft. Drag
  and keyboard order, stable dependencies, whole-draft validation/focus, Cancel
  and retry after partial binding save are preserved. Narrow screens offer Back
  to tasks. See [request automation](../integrations/netratel-orchestrator.md).
- The shared For column wraps complete long names, unbroken values, email
  fallbacks and Unicode in default/custom rendering across all three ticket
  modules and active/historic views. Subject, picker/navigation and stacked
  DataLabels remain usable without changing stored customer values.

## Verification and limits

Focused acceptance passed: 64 application logging and 159 deployment cases;
117 chat owning cases and five browser cases; 36 editor cases, seven browser
cases and four actual Chromium 200% zoom cases; 23 table rendered cases and
20 browser cases. Source review, computed geometry, synthetic before/after
screenshots and actual Docker HostConfig/recreation/controlled rollover receipts
are retained in the [delivery register](../implementation/2026-11-07-beta-delivery.md).

Actual official Netclaw 0.28.1 with a controlled loopback model passed ticket and
organization continuations through the production manager/client and disposable
PostgreSQL store: one operator input, two native turns/replies, live pending
then clear child snapshots, 13 durable events and zero resends. This establishes
connected-daemon behavior with a model fixture, separately from mocked transport,
external-model quality, historical replay and operator deployment.

No database migration is introduced. Existing SQLite/PostgreSQL compatibility,
authorization, saved connections and credentials remain. Native AI chat retains
its PostgreSQL requirement. Legacy missing child fields end ordinary chats as
before. Outcomes missed during disconnect/restart can remain unknown where the
supported protocol lacks authoritative exact-turn replay. #308/#351 remain
separate; no task/child/mutation is resent and no approval is automatic.

## Operator testing after upgrade

1. Follow the existing upgrade guide with exact `0.1.3-beta.6` image tags or recorded
   digests for API, Web and HTTP MCP, and matching CLI/stdio archives. Preserve
   the deployment's ordered Compose sources, project/context, state, volumes,
   ingress and credential ownership. Use its normal owner/apply workflow.
2. Review the effective logging policy. Check actual Docker
   `HostConfig.LogConfig`; adding rotation to an existing deployment requires
   explicit owning-source changes and affected-container recreation. A process
   restart or `docker restart` keeps the old HostConfig. Each replica has its own
   budget. Override `RATELDESK_DOCKER_LOG_MAX_SIZE` and
   `RATELDESK_DOCKER_LOG_MAX_FILE` as needed; string examples are in the retention
   guide. Application Options cannot update Docker HostConfig.
3. Confirm default diagnostic noise is absent while Warning/Error remain visible.
   Temporarily set `RatelDesk__Logging__MinimumLevel=Information` or a narrow
   `RatelDesk__Logging__Overrides__<category>=Debug` (case-insensitive longest
   prefix). Shipped Compose maps `RATELDESK_LOG_MINIMUM_LEVEL`; category keys
   belong in the service environment. Recreate containers after environment edits;
   restart direct processes. Verify configured OTLP/custom delivery and, if console
   is enabled, one console record. Restore the desired policy afterwards.
   On disposable stdio setup, test initialize at default/verbose levels and an
   invalid level: protocol-only stdout, diagnostics on stderr, invalid exit 78.
4. In disposable ticket and organization conversations on supported Netclaw,
   send one harmless delegated request. Observe pending work, its later final
   reply and clear state without a second input. Refresh/navigate/fullscreen
   and reload history. Check approvals retain their original choices. Stop or
   interrupt a separate test and verify truthful uncertainty without a resend.
5. Open a synthetic request form from Service Explorer at laptop/mobile widths
   and enlarged zoom. Select each mixed task, edit across all tabs, move by drag
   and keyboard, save/reload and check dependencies/mappings. Check hidden errors
   focus their tab/task. Cancel discards unsaved edits; after a partial save it
   cannot undo the saved form. A controlled binding-save failure must retry
   persistence on that same form, without duplicate forms/bindings.
6. Open active/historic incidents, requests and changes with short, long spaced,
   unbroken, email and Unicode requester values. Check wrapping, Subject and
   controls with an expanded sidebar, through the 1280px stacked boundary and
   mobile. On a disposable incident/request, pick a long value, navigate away
   and Back, then reload to check its complete saved value.

## Distribution

Root `Directory.Build.props` exclusively owns `0.1.3-beta.6`. Release preparation
and exact-current-main normal CI precede the existing hosted release workflow.
The complete distribution contains three amd64/arm64 image families with immutable
digests and SBOM/provenance, CLI/stdio archives for Linux x64/arm64 and Windows
x64, the corrected deployment archive, SHA256SUMS and release manifest with its
detached checksum. Publication is a prerelease with latest=false; stable latest
is preserved. The public release and independent download/pull receipts are
separate from source acceptance and later operator deployment.
