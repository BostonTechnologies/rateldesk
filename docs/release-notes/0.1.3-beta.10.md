# RatelDesk 0.1.3-beta.10

Delivers [campaign #381](https://github.com/BostonTechnologies/RatelDesk/issues/381),
including #380 and #382–#394. The compatible provider is **NetRatel 0.1.5-beta.5**.
The [delivery register](../implementation/381-premium-campaign.md) records
implementation, scoped acceptance and the separate hosted/distribution gates.

Legitimate enabled local users and administrators can submit for themselves
without an existing customer-auth link. Ownership comes from the persisted
account and domain-user membership, with an explicit eligible organization and
the saved automation binding. Matching an unrelated email never grants ownership
or moves an existing contact. Existing linked/OIDC and authorized on-behalf flows
remain supported. Failed submissions keep the input and stable submission ID,
show bounded actionable errors and permit correction/retry without duplicate work.

Automation now records per-attempt timing, deadline checks, leases and workflow
versions. A bounded indexed worker survives restart and checks only the recorded
connection, tenant mapping, request, run and attempt. When termination cannot be
confirmed at the deadline, the task shows **Timed out — outcome unknown / Needs
reconciliation**. Dependent work stays blocked; this state does not invoke
ordinary failure/Continue handling, create a confirmed-failure incident, or retry
or submit provider work. A valid late result updates the same attempt once,
recomputes its parent and clears only the uncertainty hold. Independent operator
holds remain. Historical timing and exact recovery identifiers are retained.

Request details use the existing scoped SSE infrastructure for committed task,
workflow and header updates while Tasks is visible. Authoritative snapshots,
coalescing, reconnect/resume recovery and stale-response guards preserve the
selected tab, expanded content, focus and unsaved drafts. Stream authorization
continues through its lifetime. The quiet layout keeps recovery and operational
actions available with Live/Reconnecting/Updates paused and manual refresh.

Self Service has one navigation entry with URL-backed Service Catalog and My
Requests tabs. Catalog cards keep three explicit desktop tracks, two on tablet
and one on mobile, including sparse results. My Requests and the Team, Customers,
Organizations and Categories directories query the complete authorized dataset
before count/sort/paging, use stable ties and 25/50/100 page sizes, and retain
deliberate query state. Customer access status is loaded in bounded queries.
Legacy list/typeahead contracts remain compatible; category administration uses
exact type filtering. Organization mappings retain saved IDs during catalog errors.

Team separates reversible Enable/Disable from **Delete application user**.
Supported deletion retires the application/domain identity, revokes application
sessions and credentials, removes it from active directories and retains historical
attribution and the identity fence. Repeated deletion is explicit and a retired
identity cannot silently provision again. Self/last-admin, dependency and delegated
boundaries remain enforced. External IdP accounts remain managed by that provider.
Identity-bound customer contacts cannot be removed to bypass these fences. See
[the account lifecycle](../security/rbac.md#application-user-deletion).

System connection cards distinguish configuration from never-tested, recent,
stale and failed test snapshots while retaining saved mappings and operations.
Service Explorer cards have equal geometry and labelled bounded assignment lists.
Operations Overview retains dynamic state counters and all three recent feeds,
with role-specific variants and truthful refresh state. Global search displays
the effective application name with RatelDesk fallback, preserving Shift+S,
typing exclusions, Escape and focus return.

## Upgrade and compatibility

1. Back up the domain and identity databases together with persistent protection
   keys. Test against an isolated restore before the owner rolls out production.
2. Upgrade NetRatel to **0.1.5-beta.5** first. It adds authenticated exact-attempt
   execution receipts and commits authorized ingest-replay projection recovery;
   that provider update adds no migration or new pairing/scope requirement.
3. Replace older RatelDesk API/worker replicas and apply the normal forward
   migrations for both supported stores. This release adds stable submission
   receipts, identity-bound requester contacts, durable attempt deadlines and
   leases, workflow/hold versions and application-user retirement. Preserve saved
   connections, tenant mappings, protected credentials, current runs and history.
4. Keep SQLite/PostgreSQL migration histories. Identity-bound contacts may share
   an email with unrelated legacy contacts. Do not repair links or organizations
   with SQL. A downgrade across this identity migration requires restoring the
   matching database/key backup; reverse migration is deliberately unsupported.
5. Confirm Web/API version and exact source/digests, provider version and current
   saved mapping before admitting work. An older/unavailable provider leaves an
   unconfirmed execution in reconciliation; it cannot establish remote termination.

See [pairing and upgrade details](../integrations/netratel-pairing.md#durable-execution-and-requester-upgrades)
and [execution timing/recovery](../integrations/netratel-orchestrator.md).
No production rollout is implied by build, synthetic acceptance or publication.

For deadline recovery, hold a real terminal callback and make the provider receipt
temporarily unavailable, then restart RatelDesk. At the persisted deadline verify
the original attempt becomes outcome unknown, recovery remains reachable and
dependent work, Retry/Continue and confirmed-failure incidents stay blocked. Restore
the provider/read and release the original callback. Confirm exactly one admission,
the same request/task/attempt, one late transition and dependency recovery. Repeat
with an independent operator hold and with an old-attempt callback: the independent
hold must remain and the obsolete attempt must not mutate current work.
