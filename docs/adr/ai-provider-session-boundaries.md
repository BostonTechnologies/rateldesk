# AI provider session boundaries

RatelDesk retains its existing HTTP event replay, chat store, UI and scoped command routes. Netclaw parses SignalR frames in its adapter and keeps its existing connection owner, admission checks and continuation rules. OpenAI uses the managed Agents API through a typed .NET HTTP client. The official .NET client surface checked during implementation provides Responses but does not expose the full managed session contract. [Feature #436](https://github.com/BostonTechnologies/RatelDesk/issues/436) · [OpenAI .NET SDK](https://github.com/openai/openai-dotnet)

OpenAI admission writes a durable dispatch with the operator message. A PostgreSQL lease serializes provider observation per conversation across API replicas. Workers reserve each submission before sending it and reconcile saved items and pending actions by opaque provider identity. A lost create response with no confirmed remote identity remains unresolved. Provider item receipts share the transaction that appends local replay events. Browser replay uses RatelDesk sequence numbers. [OpenAI recovery](https://developers.openai.com/api/docs/guides/agents-api/sessions/events#how-to-recover-a-disconnected-stream)

Each OpenAI session has a scoped, revocable MCP read credential and a pinned profile revision. The selected business write uses an explicit root function with a durable application-owned human decision. The gateway allows no direct session writes. Accepting an approval reserves one execution, and an uncertain downstream write stays uncertain. [OpenAI functions](https://developers.openai.com/api/docs/guides/agents-api/tools/functions)

The hosted variant provisions a bounded sandbox from a trusted, versioned package and saves authorized completed artifacts before cleanup. Codex App Server, Claude Managed Agents, Microsoft Copilot SDK and Microsoft Agent Framework remain future adapter options. [Hosted sandbox](https://developers.openai.com/api/docs/guides/agents-api/environments/openai-hosted)
