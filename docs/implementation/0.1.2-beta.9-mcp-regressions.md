## Reproduce source verification

Use the pinned SDK, Docker for PostgreSQL cases, and an isolated checkout:

```sh
dotnet build Helpdesk.sln
dotnet test Helpdesk.sln --no-build --logger "trx;LogFileName=helpdesk-tests.trx" --results-directory TestResults
tools/ci/validate-layout.sh
python3 tools/ci/validate-docs.py
python3 -m unittest discover -s tests/http_mcp -p 'test_*.py'
```

The HTTP/stdio tests use real hosts with synthetic backends or isolated application
databases. Relational HTTP tests use real routes and fresh readback scopes.
TRX output is retained by the normal `.NET validation` CI job. This branch includes
the unchanged [PR #248](https://github.com/BostonTechnologies/RatelDesk/pull/248)
harness foundation at `d0a9d3a80eaaa40a6c3a27d711701c11549e844c` and extends it.
Use [campaign testing](../mcp-http/campaign-testing.md) for separately authorized
live reads with a fresh profile, candidate catalog and evidence directory. The
exact deployed beta.9 must receive a fresh campaign before any readiness verdict.
