# NR ↔ RD pairing v1 (9 October 2026)

JSON camelCase, fixed routes `/api/pairing/v1`, `contract: "bostec.pairing.v1"`.
Installation IDs and mapping IDs are GUID `D` strings. Tenant IDs are strings (NR positive integer string, RD organization GUID/string). Pair ID is lowercase SHA256 hex of ordinal-sorted installation D strings joined with `:`. Server derives it; labels never identify peers.

`PairingMetadata(contract, product, installationId, name, webOrigin, apiOrigin, producerInstanceId, signingPublicKey)` where product is `netratel` or `rateldesk`; producerInstanceId is the existing stable Flow producer GUID for NR, null RD. GET `/metadata` at either public Web/API origin sends `X-Pairing-Nonce` fresh 32-byte base64url nonce (43 characters) and returns `PairingMetadataProof(metadata, nonce, signature)`; signingPublicKey is base64 DER SubjectPublicKeyInfo of existing RSA signing key and signature is RSA SHA256 PKCS1 over UTF8 camelCase JSON metadata + `:` + nonce. Verify proof from entered origin, then canonical API must sign the fresh challenge with exactly the same public key and metadata. Public Web fixed proxy forwards nonce. Pin key in peer metadata. Canonical API origin is accepted only after a GET at its same fixed metadata route returns identical installation/product/web/api metadata. Credentials/token routes are fixed, no arbitrary advertised paths.

POST `/exchange`: `PairingExchangeRequest(code, operationId, peer, inboundSecret, signature)`; response `PairingExchangeResponse(pairId, peer, inboundSecret, signature)`. Exchange signature uses the caller installation key over the complete compact camelCase JSON request with signature set to the empty string. The exchange response is signed over its complete compact camelCase JSON with signature set to the empty string and is verified with the discovered receiver key. Receiver discovers and verifies caller metadata and verifies that operation signature; an existing peer must match its pinned key/identity. InboundSecret is 32 random bytes base64url (43 characters), stable for this active peer pairing. Generator consumes code atomically; operation GUID + peer installation ID + complete request fingerprint binds the protected response replay for at most 10 minutes. One active code per installation, 8 random readable characters formatted XXXX-XXXX, expires in five minutes. Wrong/expired code cannot redeem. One unique peer row and transaction/CAS prevent replicas/opposite initiation duplicates. Secret never reaches browser; protect initiating attempt before exchange. Authenticated local generate/pair uses current human administrator only.

Setup requests use `Authorization: Pairing <secret>` and `X-Pairing-Peer: <caller installation GUID>` and `X-Pairing-Caller: <lowercase SHA256 of caller inbound secret>`. Handler hashes incoming secret, verifies current nondeleted pair and the caller generation against its protected outbound secret, and loads the retained local administrator's current setup authority. It never creates a business ClaimsPrincipal.

GET `/directory`: `PairingDirectory(tenants, customers)` of `PairingChoice(id, name, parentId)`; tenants are NR tenants or RD organizations; customers RD only, parentId organization ID.

PUT `/mappings/{mappingId}`: `PairingSaveRequest(operationId, revision, mapping, credential)` with `PairingMapping(id, pairId, name, netRatelTenantId, ratelDeskOrganizationId, ratelDeskCustomerId, createIncidents, runAutomation)`; credential is caller-issued scoped business credential or null if no inbound business capability. Response `PairingSaveResponse(mapping, credential)` with credential target-issued or null. Revision starts 1; revisions and operation/fingerprint bind safe retry; deleted mapping tombstone always rejects delayed save. Local endpoint first persists nonsecret draft and protected offered credential for retry, peer finalizes using its retained owner, local completes after authenticated peer response. An active mapping + current owner authority gates every business use; before Save setup secrets allow directory/save/test/delete only. Failed local finalization returns same draft, never new card.

`PairingBusinessCredential(clientId, clientSecret, tokenEndpoint, audience, issuer, scopes, sourceInstanceId, sourceNamespaceId)` uses existing `/connect/token` business OAuth JWT paths (NR token path confirmed separately). sourceNamespaceId = mapping GUID; sourceInstanceId = stable NR producer GUID for incident credentials; callback-only credentials have neither source ID. Tenant-specific business principals are only created after mapping tenant validation, initially pending/nonissuable; local finalized active mapping gates token issuance and every use. Offered credentials never grant business permission before final Save completes. NR issues automation credential; RD issues incident and callback credential according to selected capabilities. Automation stores the authorized real tenant; each use derives and checks exact current authorized jobs and active agents under the retained administrator. An empty catalog at Save grants no job or agent. Exact scopes and fixed protocol business paths remain existing owning receiver/orchestration scopes.

POST `/mappings/{mappingId}/test`: returns `PairingTestResult(success, message, testedAtUtc)` checks current pair + mapped resource current authority + selected inbound/outbound scopes without incident/task. Optional.

Pair/mapping generation and revision fences bind all asynchronous writes, retries and hidden cleanup so delayed operations cannot resurrect access or delete a newly paired generation.

DELETE `/mappings/{mappingId}` and DELETE `/pair` idempotently revoke local immediately; tombstones prevent resurrection. Last mapping removal deletes pair credential authority. Peer cleanup bounded background record is hidden, protected and expires; offline peer is never claimed to acknowledge.

Authenticated human API: `/api/v1/admin/system-connections`: GET list; POST `/code`; POST `/pair` with `PairingConnectRequest(address, pairingCode, operationId)`; GET `/{pairId}/directory` combines local and authenticated remote choices; PUT `/{pairId}/mappings/{mappingId}` accepts `PairingMapping` only; POST `/{pairId}/mappings/{mappingId}/test`; DELETE corresponding mapping or `/{pairId}` for unused pair. List includes paired incomplete row and each saved mapping with peer/address/names/capabilities/status/test result.

Upgrade revokes all old NR↔RD service principal secrets/deployment/manual registrations and receiver bindings; clears protected old orchestrator/connector secrets and disables obsolete binding use. Drops old attempt/operation/verification/rotation tables via new forward migration. Preserve historical migrations, installation/producer/signing identities, Netclaw and unrelated human/API/MCP/business history. No old coordinator or manual NR↔RD fallback ships.
